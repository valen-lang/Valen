# Fill `lock_weak_macro`'s `borrow_coord`

## Context

`generate_function_body_lock_weak` (`FrontendRust/src/typing/macros/lock_weak_macro.rs:39`) opens with

```rust
let borrow_coord = unimplemented!();//KindT::new(OwnershipT::Borrow, param_coords[0].tyype.region, param_coords[0].tyype.kind);
```

so any program that *scouts* `weak.vale` dies there. It is currently the joint-largest simple
cluster at **7 tests**, six of which are `compiler_project_tests::typing_pass_*` — whole-program
tests that load the full builtins and reach `lock` without using it.

`weak.vale` declares the whole surface:

```vale
extern("vale_lock_weak")
func lock<T>(w weak T) Opt<&T>;
```

The parameter is `WeakRef(T)`; the return contains `BorrowRef(T)`. `borrow_coord` is the type
`get_option` wraps an `Opt` around, so it is the borrow of the weak's pointee. The commented Scala
says the same thing in Coord vocabulary: take the parameter's kind, make it a Borrow. Under the
onion the three-part `CoordT` collapses to one wrap, which is the whole of this change.

## The change

`FrontendRust/src/typing/macros/lock_weak_macro.rs` — replace the `unimplemented!()` with a match
that peels the weak and rebuilds it as a borrow:

```rust
// `lock` takes a `weak T` and hands back an `Opt<&T>`, so the Opt is built around a borrow of the
// weak's pointee. The Scala threaded the parameter's region; a WeakRefT carries none, and the
// get_option call below already passes RegionT::Default.
let borrow_coord = match param_coords[0].tyype {
    KindT::WeakRef(w) => KindT::BorrowRef(
        self.typing_interner.alloc(BorrowRefT { inner: w.inner, region: RegionT::Default })),
    other => panic!("lock's parameter must be a weak: {:?}", other),
};
```

Reuse rather than invent:

- `peel_one_reference` (`typing/templata_compiler.rs:74`) is the alternative to the match, but the
  match is better here — it states that the parameter *must* be a weak, which `peel_one_reference`
  would silently accept for any wrap.
- The `BorrowRefT` construction mirrors the one live idiom, `compiler_solver.rs:1220`.
- No import needed beyond what `use crate::typing::types::types::*` already brings in.

Everything downstream is already wired: `get_option`
(`typing/expression/expression_compiler.rs:1691`) resolves `Opt<contained>` and returns the opt
kind plus both constructors and impl ids, and `LockWeakTE::new` takes them as-is.

## What this does NOT unblock, and why it matters

**`lock_weak_member` will not go green from this change**, and it should not be treated as the
acceptance test. Its program still uses the retired `&&`-as-weak spelling at two sites
(`compiler_tests.rs:4007` `origin &&Base;` and `:4021` `&&base`). Under the current model `&&T` is
a genuine double borrow, not a weak, so:

- the field types as `BorrowRef(BorrowRef(Struct(Base)))` and will not satisfy `lock`'s `weak T`;
- the expression `&&base` routes to the weak-expression path, whose `ShareT` arm is still
  `panic!("implement: Ownershipped ShareT LoadAsWeakP")` at `expression_compiler.rs:741`.

That test is one of the hand-list sites the handoff records under "**the `&&`-as-weak corpus
sites** — the compiler cannot drive this migration, because `&&T` stays a legal type and nothing
errors." Migrating it is a separate decision (see Open questions).
