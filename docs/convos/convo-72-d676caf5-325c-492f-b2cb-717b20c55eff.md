`diagnose` rule 1 is *"find the first place where things go wrong… trace backward from the symptom to the earliest point where reality diverges from expectation."* `bug-repro` step 2 is *"Diagnose. ## Where the seams actually are

**Nothing says which to reach for, or in what order.** Facing a panic, all three are plausible. The real chain is: a crash report tells you it broke → `diagnose` finds why → `bug-repro` locks it into a test. Each file is silent about the two on either side of it.

**Minimality means two different things.** `bug-repro`'s reduction is about the *program* — smallest input that reproduces. `crash-report`'s "one failure, one run, one test" is about the *report's scope*. They compose well (a reduced repro makes a much better lead-in) and nothing notes it.
