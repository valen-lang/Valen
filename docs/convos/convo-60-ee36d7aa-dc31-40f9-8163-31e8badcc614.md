## 🤖 Claude

Three different jobs on the same data, at three stages of its life — plus one genuine redundancy worth knowing about.

## The layering

**`extract-conversation`** — the **producer**. JSONL → Markdown, via the `claude-extract` fork at `/Volumes/V/claude-conversation-extractor`. It's a *global* skill (`~/.claude/skills/`), not a project one, so it works in any repo and writes wherever the extractor puts it. Nothing to do with convos as a chain; it just turns one session log into readable text.

**`read-convo`** — the **locator**. Given a session id, find the doc by its head stamp (never by filename glob — legacy docs have no id in the name), then follow the recorded lineage: `continues:` if present, `opened:` as a fallback with the caveat that it records what was *consulted*, not what was *continued*. Its whole value is the two things you'd get wrong by hand: stamp-not-filename, and those two fields not being interchangeable.

**`full-read`** — the **mechanic**. 14 lines: `Read` in 500-line chunks, don't `wc -l` first, finish one file before opening the next. Both of the above delegate to it, and so does anything else facing a big file. It isn't about convos at all — it exists because these docs run to thousands of lines and the default instinct (skim, or read a slice) silently loses most of the content.

So: `extract` writes it, `read-convo` finds it and its ancestors, `full-read` is how you actually get it into context. Plus `continue-session`, which is the write-path twin of `read-convo` — it *declares* the link rather than following one, which is why convo-59 decided against merging those two.

## The one real redundancy

`extract-conversation` overlaps with **Guardian's own exporter**, which sweeps this repo's sessions into `docs/convos/` every 30 seconds — including minting a doc for a session that doesn't have one yet. In Vale2, nothing needs `claude-extract`: the doc already exists before you ask for it, and Guardian is the single writer of that directory, so extracting into it by hand would be clobbered.

What keeps `extract-conversation` earning its place is that it's global and Guardian isn't: it's the way to get a transcript out of a repo with no Guardian, or to dump an arbitrary session somewhere outside `docs/convos/`. Its description doesn't say that, which is why it reads as a duplicate of the exporter. A line in its frontmatter noting "Guardian-managed repos export automatically; use this elsewhere" would settle it — say the word and I'll add it.
