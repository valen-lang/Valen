# Accuracy report: Specifying Regions In Expressions (SRIE)

Audited against the working tree on 2026-09-06. Source: git 24695a17^:docs/regions/Regions.md lines 533-579 (deleted wholesale in the 24695a17 docs-tree flatten, along with all of `docs/regions/`).

## Verdict
The recovered text describes a Scala/early-Vale-era multi-region generics design — an explicit `x'` call-site prefix that specifies an output region, unified by the compiler with the callee's own trailing region generic parameter (`o'`), with a fallback to the "callers' default region" when omitted. None of this exists in the current Rust typing pass: `RegionT` is a two-variant enum (`Iso`, `Default` — src/typing/types/types.rs:16-20) with no per-call region unification, and region generic parameters are explicitly *filtered out* of `generic_params` by the postparser so they are never solved as identifying runes at a call site (src/typing/rust_interop/declarations.rs:172-179, 695-698) — the exact opposite of SRIE's central claim that the caller's region gets equated with the callee's declared output-region parameter. The only surviving artifact is the `// See SRIE` comment at src/typing/expression/expression_compiler.rs:670, which cites the doc merely to explain why `nenv.default_region()` is passed in for a call's arguments — a citation to the "when omitted, use the default region" side note, not to the (now-fictional) explicit-region-syntax mechanism. This is an abandoned early design, not a description of current behavior: obsolete. Recommendation: delete the `// See SRIE` comment (replace with a plain inline note about why the default region is used, or point at whatever doc currently governs `RegionT`/groups) and do not migrate this text into docs/arcana.

## Stale citation sites
src/typing/expression/expression_compiler.rs:670 — the comment `// See SRIE` sits above `nenv.default_region()` being passed as the region argument when evaluating a `FunctionCall`'s arguments through an `OverloadSet`. This is defensible as citing "claim 4" (the default-region fallback), which is still true, but the arcana it points to is 90% about a call-site region-unification mechanism (claims 1-3, 5) that no longer exists. A reader following the citation today would learn about a nonexistent `x'` syntax rather than why `default_region()` is used here.

## Uncited sites that embody the arcana
None found. The current region model (`RegionT::Default`/`Iso`, per-parameter borrow groups) is a different mechanism (see borrow_checker_enabled / groupify.rs / aliasing_info.rs) already documented via its own in-progress arcana (e.g. handoffs in docs/handoffs/borrow-checker-handoff.md), not SRIE's call-site-region-unification idea. Nothing in the tree implements SRIE's actual claims, so there is nothing to cite it from.

## Suggested text
Not applicable in the arcana sense — SRIE's mechanism was never built and the current region/group system works differently, so there is no corrected concept to hand the maintainer.
