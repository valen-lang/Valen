# Accuracy report: Translate Impl Bound Argument Names For Case (TIBANFC)

Audited against the working tree on 2026-09-06. Arcana section: docs/arcana/Generics.md:1461 ("### Translate Impl Bound Argument Names For Case (TIBANFC)")

## Verdict
The core idea (impl bound arguments, when carried into an override-dispatcher case, must be translated out of impl-placeholder terms into case terms, or lookups fail) is still true of the current compiler, and `src/instantiating/instantiator.rs:745-835` (`translate_override`) is a live piece of code embodying exactly this concern. But the doc is stale in three ways: it still calls the responsible object a "Monomorphizer" (Scala-era name; the Rust type is `InstantiatorI` / `DenizenBoundToDenizenCallerBoundArgI`), the fix it prescribes ("translate those full names" at instantiation time) is not how the current code solves the problem — the translation now happens earlier, in the typing pass (`src/typing/edge_compiler.rs`, which precomputes `OverrideT::dispatcher_and_case_placeholdered_impl_reachable_prototypes` already phrased in dispatcher/case terms), and the one citing test (`template_overrides_are_stamped` in src/integration_tests/tests/integration_tests_b.rs:654) is `unimplemented!()` and `#[ignore]`d, so the example is not actually exercised. The doc's own ZHERE self-notes (Generics.md:1455-1459) already flag the heading and a level-inversion wording problem as unresolved, confirming this section is known-stale and not yet cleaned up.
