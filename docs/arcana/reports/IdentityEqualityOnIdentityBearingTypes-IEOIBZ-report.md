# Accuracy report: Identity Equality On Identity-Bearing Types (IEOIBZ)

Audited against the working tree on 2026-09-06. Arcana doc: docs/arcana/IdentityEqualityOnIdentityBearingTypes-IEOIBZ.md

## Verdict
The core mechanism (identity types implement `PartialEq`/`Eq`/`Hash` via `std::ptr::eq`/`std::ptr::hash`ing `&self`, and wrappers just `#[derive(...)]`) is still real and correctly followed at every code site checked — `FunctionHeaderT`, `IdT`, `LocalVariable`, `CapturedVariableT`, `LocalVariableI`/`CapturedVariableI` (instantiating pass), and `IEnvironmentT`. However the doc's "Where" enumeration is factually wrong on two counts: it lists `IEnvironmentT` as a "manual ptr-eq" identity type when the code shows it is actually a `#[derive(PartialEq, Eq, Hash)]` polyvalue wrapper (the *other* category the doc itself defines), and it names four types — `FunctionA`, `StructA`, `InterfaceA`, `ImplA` — that no longer exist anywhere in the repo. `FunctionTemplataT`/`StructDefinitionTemplataT`/`InterfaceDefinitionTemplataT`/`ImplDefinitionTemplataT` (which the doc separately and correctly lists as derive-wrappers) now hold `&'t IdT` + `IEnvironmentT` directly, not references to any `FooA` struct. This is a concrete FALSE claim plus stale type names in the doc's most load-bearing table, so this is major-inaccuracies rather than a wording nit.

## Stale citation sites
- docs/arcana/IdentityEqualityOnIdentityBearingTypes-IEOIBZ.md:22 (the "Where" line itself) — see Claim 4 above; this is the doc's own text being stale against src/typing/env/environment.rs and src/typing/templata/templata.rs, not a separate citation site, but it's the most consequential inaccuracy.
- src/typing/env/environment.rs:1183-1186 — the comment there says comparisons via `IEnvironmentT` "go through that enum's ptr-eq impl directly," but `IEnvironmentT` has no ptr-eq impl (it derives, per Claim 4); functionally the chain still lands on identity comparison (derive → variant ref → `PackageEnvironmentT`'s manual `id == id`, or another arena type's `ptr::eq`), so the outcome is correct but the phrase "ptr-eq impl" mischaracterizes `IEnvironmentT`'s own impl.

## Suggested rewrite
Replace the "Where" bullet at docs/arcana/IdentityEqualityOnIdentityBearingTypes-IEOIBZ.md:21-24 with:

```
**Where:**
- Identity types with manual ptr-eq impls: `FunctionHeaderT`, `LocalVariable`, `CapturedVariableT` (and their instantiating-pass counterparts `LocalVariableI`/`CapturedVariableI`). (`IdT` is the slight outlier — it ptr-eq's `package_coord` and the `init_steps` slice pointer, and structurally compares `local_name`, rather than ptr-eq'ing the whole struct, because `IdT` is Copy and lives by value, not by reference.)
- Wrappers that just derive: `IEnvironmentT` (Polyvalue enum over the variant env types), `FunctionTemplataT`, `StructDefinitionTemplataT`, `InterfaceDefinitionTemplataT`, `ImplDefinitionTemplataT`, `ContainerInterface`/`Struct`/`Function`/`Impl`, `ExternFunctionTemplataT`, plus most TFITCX Value-types in `templata.rs`. These wrappers now hold `&'t IdT` (and/or `IEnvironmentT`) directly rather than a reference to a dedicated identity struct per definition kind — there is no `FunctionA`/`StructA`/`InterfaceA`/`ImplA` type in the current codebase.
- Variant env types (`PackageEnvironmentT`, `FunctionEnvironmentT`, etc.) use `self.id == other.id` rather than ptr-eq. That's correct given `IdT` is sealed/canonical, and these are usually compared through `&'t IEnvironmentT` — via `IEnvironmentT`'s own derived `PartialEq`, which delegates into these types' manual id-eq — anyway.
```
