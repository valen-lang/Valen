# Accuracy report: Bound Return Resolution (BRRZ)

Audited against the working tree on 2026-09-06. Arcana doc: docs/arcana/BoundReturnResolution-BRRZ.md

## Verdict

The doc's core mechanism claim is still roughly correct (`ResolveSR`'s puzzle in `src/typing/infer/compiler_solver.rs` has a two-mode puzzle list, `[params, return]` and `[params]`, matching the doc's "second handler branch"), and the mechanism's guard comment does appear verbatim in `src/typing/infer_compiler.rs:1236` referencing `@BRRZ`. However, the doc itself already carries a self-appended "VCOORD: update this entire doc" section (lines 36-45) that flags concrete drift the doc's own prose has not been reconciled with: a stale line number for the `arrays.vale` bound, a retired builtin type-param list, retired call syntax, an unresolvable `SROACSD` citation, Scala-spelling function names that don't match the Rust code, and a missing pointer to the impl-bound sibling family. Beyond those self-flagged issues, one of the three test citations (`after_regions_tests.rs:577`, `brrz_nested_bound_return_inference_through_a_lambda_body`) is currently `#[ignore]`d, which the doc's prose doesn't acknowledge — it presents BRRZ as a working capability without noting that the nested-lambda edge case is disabled. Net: minor-inaccuracies — the core idea and citation sites are intact, but several concrete details (line numbers, syntax, function names, one open citation) are drifted and the doc knows it.
